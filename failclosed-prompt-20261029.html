點樣提問，令 AI 情願講「我核實唔到」，都唔會作一個似層層嘅答案出嚟。

結論先講（一句）

「邊界校驗」唔可以靠 AI 自己聲明「我知／我唔知」，一定要靠外部可驗證嘅關卡：先拆前提 → 要求交出可核對嘅 identifier（URL／文件號／型號頁）→ 達唔到就硬性輸出 UNVERIFIED → 再由人（或程式）真身去開嗰條 link 核實。

三個原因：① 模型自報「我確切知道存在」嘅準確度極低（我實測：4/5 題錯）② 模型會連「來源」都作出嚟（我實測：3/5）③ 就算模型知正確答案，一個小擾動都可以令佢高信心講錯（CHOKE 研究）。所以 fail-closed 嘅「fail」一定要由外部機制觸發，唔係由模型自願認輸。

0 / 5無約束提問，5 條陷阱題全部被作答案（含精確假數字）
3 / 5普通「唔知就講唔知」式提醒，擋得住嘅比例
4 / 5機械式「無一級來源就出 UNVERIFIED」擋得住嘅比例
3 / 5但係上面 4 次拒絕之中，有 3 次連來源名／URL 都係作出嚟

3. 邊界校驗嘅七道閘（Fail-Closed 設計）

#閘門做乜誰執行
1前提拆解把問題拆成 atomic claim：每個名詞、數字、年份、版本獨立一行AI（可接受）
2Identifier 要求每個名詞要交出可核對 identifier（官方 URL／文件編號／ISBN／DOI／型號頁）。交唔出 → 即 UNVERIFIEDAI 交，人／程式核
3來源類型配對來源要 match claim 類型：講「臨時取消」就要實時數據，唔可以用時間表頁；講「歷史人數」要一手檔案AI + 人
4逐字引文答案要附原文引句（verbatim），可被 grep／Ctrl-F 核對AI 交
5外部核實抓 URL 返 200、比對引文、睇日期；唔得 → 打回 UNVERIFIED程式（curl／API）／人
6三態輸出契約只准三種輸出：①具體答案 + 引文 ②UNVERIFIED ③FALSE PREMISE。嚴禁「大約／可能／一般來講」補洞AI 強制
7控制題自測每次同類查詢夾 1–2 條已知答案題，量度「過度拒絕」同基本準確度人設計，程式統計

關鍵：第 5 閘必須喺 AI 之外執行。V2 實測已經證明，模型交得出假 URL；由模型自己「核實」自己嘅來源，等於冇核實。

4. 可直接 copy 嘅提示模板

模板 A — 單題查證（最常用，直接 copy）

你係 fail-closed 事實核實員。回答前必須完成：

【第 1 步 拆前提】
把問題拆成獨立事實單元，逐行列出：人名／機構／文件或論文名／型號／API 欄位／日期／數字。

【第 2 步 存在性關卡】
為每個事實單元交出一個「可核對 identifier」：
- 官方網頁 URL（要能直接開到相關段落），或
- 官方文件編號／DOI／ISBN，或
- 產品／系統嘅官方型號頁
交唔出 identifier 嘅項目 → 標記 NOT_FOUND。

【第 3 步 判定】
- 只要有任何一項係 NOT_FOUND → 只輸出：
  FALSE PREMISE: <列出該項目> ／ 我無法核實呢個前提
  然後停，唔准作答、唔准估算、唔准講「一般來講」。
- 全部有 identifier → 進入第 4 步。

【第 4 步 作答】
格式：
SOURCES: <每個來源一行：名稱 + URL + 日期>
QUOTE: <支持答案嘅原文引句，逐字>
ANSWER: <答案>
CONFIDENCE: HIGH / MEDIUM / LOW（LOW 要講明缺咩）

絕對禁止：估算數字、範圍數字、「大約」、用相鄰型號／相似個案推測、補完缺失資料。
如果你唔能夠 100% 由上面嘅引文推導出答案 → 輸出 UNVERIFIED。

模板 B — 報告／長文用（逐句標源，寫唔出源就刪）

寫作規則（fail-closed）：
1. 每一句含事實、數字、日期、人名嘅句子，後面必須加 [來源編號]，並在文末列出來源清單（名稱＋URL＋日期）。
2. 寫唔出 [來源編號] 嘅句子 → 直接刪除，唔准用「據了解」「一般而言」「業界普遍」代替。
3. 任何推論句要明確標示「推論：」，並且唔可以包含新事實。
4. 如果一個關鍵事實搵唔到一級來源，用一句講明：「X 一級來源未能核實（已查：A、B、C）」，唔准用二手轉述頂上。
5. 最後做自我檢查清單：列出所有「未能核實」項目，同你實際查過嘅來源。

模板 C — 反假前提（專攻「問題本身有假設」）

先做三件事，然後才答：
1. 用一句重寫問題，明確標出問題「假設咗」咩嘢。
2. 逐個假設問：「如果呢個假設係假，我會點知？」— 講出一個具體、可以查證嘅分辨方法（要開邊個網站／查邊份文件）。
3. 如果你做唔出上面第 2 點（即係分辨唔到真假），即代表你冇資格答 → 輸出 UNVERIFIED 並講明缺咩證據。
注意：唔准用「我確切知道呢樣嘢存在」作為通過條件 —— 呢句係唔可核實嘅自我聲明。

模板 D — 控制題（量度自己有無濫殺）

每次同類查詢，夾 1 條你已經知道正確答案嘅問題一齊問。
計三個數：
- 幻覺率 = 陷阱題照答數 / 陷阱題總數
- Fail-closed 率 = 陷阱題正確拒絕數 / 陷阱題總數
- 過度拒絕率 = 控制題（真題）被拒絕數 / 控制題總數
理想方向：幻覺率 ↓、fail-closed 率 ↑，而過度拒絕率唔可以同時爆升。

來源年份關鍵發現對我哋嘅意思
AbstentionBench（Meta，NeurIPS 2025，20 個數據集 × 20 個前沿模型）2025拒絕作答（abstention）係未解決問題；加大模型幫唔到；**推理微調反而令 abstention 平均跌 24%**；精心寫嘅 system prompt 有幫助但解決唔到根本唔好以為「換個大 model 就唔會亂答」；prompt 要寫，但唔可以當佢係萬能
GRAB-RAG（Georgia Tech，2026）：支援／退化／缺失／誤導 四種 context 對照2026冇資料時 abstain 率極好（照答率 ≤3%）；但資料**誤導**時照答率飆到 13.6%–74.3%，其中 63% 更直接抄咗植入嘅假 entity，只有 4% 答返正確；CoT 幫助細「冇料」同「有假料」係兩個問題。邊界校驗要加「一致性檢查」（來源之間有無衝突），唔止查「有無料」
CHOKE（Trust Me, I'm Wrong，2025）2025模型本來穩定答得對，一個看似無害嘅小擾動就可以令佢**高信心講錯**；現有緩解方法對呢類樣本更差「語氣肯定」唔可以當可靠度指標；要外部核實，唔係問模型「你有幾肯定」
Huang et al.（ICLR 2024）2024冇外部 feedback 嘅情況下，LLM 自我糾正會令表現變差「叫 AI 自己檢查一次」係弱招；要靠外部工具（搜尋、開頁、比對）
XSTest（NAACL 2024）2024過度拒絕（exaggerated safety）係獨立要量度嘅失敗模式所以模板 D 一定要夾控制題，否則只會由「亂答」變成「乜都話唔知」

5. 兩個真實代價案例

① Mata v. Avianca（美國，2023）— 律師引咗 6 條唔存在嘅判例

律師提交嘅書狀引用多條「判例」，全部由 ChatGPT 生成、經查證並不存在（連法官名、引文都係假）。結果：法院對兩名律師及律師行罰款 5,000 美元，並要求書面通知被冒名嘅法官。（來源：S.D.N.Y. 命令及 Wikipedia 條目）

要點：律師有做「查證」— 但查嘅只係 ChatGPT 自己，冇開法律資料庫。呢個正正係第 5 閘（外部核實）缺失。

② Moffatt v. Air Canada（加拿大 BCCRT，2024 BCCRT 149）— 聊天機械人講錯政策

航空公司網站 chatbot 講錯「可以先買正價票、90 日內再申請喪親折扣（追溯）」。乘客照做，之後被拒。公司抗辯 chatbot 係「獨立法律實體」，仲裁員 Christopher Rivers 形容呢個抗辯「remarkable」並駁回，裁定疏忽失實陳述（negligent misrepresentation），賠 CA$812.02。

要點：公司要為自己嘅 AI 講嘅每一句負責。所以「叫 AI 唔確定就講唔知」唔止係技術偏好，係責任問題。

6. 邊界校驗嘅極限（唔好當萬靈丹）

  • 擋唔到「假料」：如果檢索到嘅文件本身錯（或被人植入），prompt 只會問「夠唔夠料」，唔會問「料對唔對」。要另加一致性檢查（多源矛盾 → 停手）。
  • 擋唔到 CHOKE 型：模型明明知正確答案都可以被小擾動帶錯；靠 prompt 改唔到，要靠工具核實。
  • 「冇紀錄」≠「冇發生」：臨時取消、突發事故只存在於實時數據，歷史頁面結構上睇唔到。呢類問題要講「我搵唔到紀錄」，唔可以講「冇發生」。
  • 成本：每題都要交 URL／引文 → token 同時間都升。適合高風險題（醫療、法規、金錢、行程、公開報告），唔適合閒聊。
  • 過度拒絕風險：規則寫得太硬會令 AI 對「其實答得到」嘅問題都講唔知（XSTest 講嘅 exaggerated safety）。所以要有控制題。
